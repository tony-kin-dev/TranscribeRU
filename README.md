# TranscribeRU

Кроссплатформенная платформа для распознавания речи (ASR) на PyTorch-движках —
с командной строкой и графическим окном. Первый движок — **GigaAM-v3**
(Conformer/RNN-T от Salute, через официальный пакет `gigaam`) с заметно лучшим
качеством на русском, чем Whisper-large-v3 (по бенчмаркам Salute средний WER
~8.4% против ~25%).

Архитектура движков-плагинов: ядро владеет декодом, нарезкой длинного аудио и
сборкой сегментов, а движок отвечает только за «звук одного окна → текст».
Добавить новый движок = один файл в `engines/` + запись в реестр.

## Возможности

- Любой аудио- **и видеоформат** через системный `ffmpeg` — из видео
  (`.mp4/.mov/.mkv/.avi/…`) берётся аудиодорожка (`.opus/.m4a/.wav/.mp3/.aiff/…`).
- Нарезка длинных файлов через `silero-vad` (MIT, **без HF-токена и gating**).
- Авто-выбор устройства: **CUDA → MPS → CPU**.
- Форматы вывода: `txt_timecoded`, `txt_plain`, `srt`, `json`.
- Два интерфейса: CLI (`transcribe-ru`) и окно (`transcribe-ru-gui`).
- Пунктуация и нормализация чисел из коробки (вариант `e2e_rnnt`).

## Как это работает

```
аудиофайл ──ffmpeg──▶ 16 кГц mono float32 ──silero-vad──▶ окна <25 с
                                                              │
                                              на каждое окно  ▼
                                      GigaAM ◀── «звук окна → текст»
                                                              │
                                                              ▼
                          сборка сегментов ──▶ форматтер ──▶ файл результата
```

Границы окон, найденные VAD, становятся тайм-кодами сегментов на выходе.

## Быстрая установка (в один шаг)

Скрипт сам поставит всё: пакетный менеджер (если нужно), Python 3.12, ffmpeg, git,
сам проект с зависимостями в отдельном окружении, и положит иконку запуска на
Рабочий стол. Где автоустановка невозможна без участия владельца — скрипт укажет
ссылку.

**macOS** — в Терминале:

```bash
curl -fsSL https://raw.githubusercontent.com/tony-kin-dev/TranscribeRU/main/scripts/install.command | bash
```

**Windows 10 / 11** — два равноценных способа:

1. **Двойной клик.** Скачайте `scripts/install.bat` и `scripts/install.ps1` в
   одну папку и дважды кликните `install.bat`.
2. **Одной командой** в PowerShell:

   ```powershell
   iwr -useb https://raw.githubusercontent.com/tony-kin-dev/TranscribeRU/main/scripts/install.ps1 | iex
   ```

> Не запускайте `install.ps1` через правый клик → «Выполнить с помощью
> PowerShell». Встроенный в Windows PowerShell 5.1 читает такой файл в
> кодировке cp1251, русский текст ломает разбор, и скрипт не стартует. Нужен
> `install.bat` или команда выше: оба пути читают скрипт как UTF-8.

Что делает установщик на Windows, по шагам:

1. Через `winget` ставит Python 3.12, ffmpeg и git. Если чего-то не хватает,
   нужен App Installer из Microsoft Store. Для git Windows может спросить
   разрешение администратора (UAC).
2. Клонирует проект в `C:\TranscribeRU`. Если он там уже есть, делает `git pull`.
3. Создаёт окружение `C:\TranscribeRU\.venv` и ставит зависимости. В первый раз
   это занимает несколько минут: одна только сборка torch весит сотни мегабайт.
4. Скачивает веса модели (~430 МБ) в `C:\gigaam_cache` с тремя попытками и
   записывает этот путь в переменную пользователя `GIGAAM_CACHE_DIR`. Если
   скачать не удалось, модель докачается при первом запуске.
5. Кладёт ярлык **TranscribeRU** на Рабочий стол.

Обе папки лежат в корне диска намеренно: C++-библиотеки не открывают пути с
кириллицей (см. «Решение проблем»). Другие папки можно задать переменными
`TRANSCRIBE_RU_DIR` и `GIGAAM_CACHE_DIR`.

После установки на Рабочем столе появится иконка **TranscribeRU** — двойной клик
открывает окно. Повторный запуск скрипта обновляет установку.

### Как поделиться с другим человеком

Не архивируйте папку проекта — так не заработает: `.venv` привязан к абсолютным
путям этого компьютера, а Python, `ffmpeg` и скачанная модель (`~/.cache/gigaam`)
лежат вне папки. Полезен в архиве только исходный код, а его проще раздать ссылкой.

Просто дайте человеку команду быстрой установки выше — она поставит всё на его
машине сама. (Нужен интернет: Python/ffmpeg/torch и модель скачиваются при установке.)

## Установка вручную (или для разработки)

Нужны:

- **Python 3.11 или 3.12** (проверено; зависимости `gigaam` могут не иметь колёс
  под более новые версии Python);
- системный **`ffmpeg`** — `brew install ffmpeg` (macOS) / `apt install ffmpeg`
  (Debian/Ubuntu) / `winget install ffmpeg` (Windows);
- **`git`** — поддержка v3-моделей пока есть только в git-версии пакета `gigaam`
  (на PyPI ещё нет), поэтому он ставится из репозитория.

```bash
python3.12 -m venv .venv
source .venv/bin/activate         # Windows: .venv\Scripts\activate
pip install -e .
```

> **Первый запуск** скачивает веса модели (~430 МБ для `v3_e2e_rnnt`) в
> `~/.cache/gigaam` — дальше они берутся из кэша. HF-токен **не нужен**.

## Использование (CLI)

```bash
transcribe-ru --audio file.opus                    # txt с тайм-кодами рядом с исходником
transcribe-ru --audio file.opus --format srt       # субтитры .srt
transcribe-ru --audio file.opus --granularity fine # короткие реплики ~5-7с (для субтитров)
transcribe-ru --audio file.opus --device cpu --out-dir ./out
transcribe-ru --audio file.opus --dry-run          # показать план, ничего не запуская
```

Пример: на входе речь «привет как дела сегодня очень хорошая погода» получится
файл рядом с исходником:

```
00:00:00
Привет! Как дела сегодня? Очень хорошая погода.
```

Прогресс печатается в `stderr`, результат — файл с тем же именем и расширением
по формату.

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `--audio` | — (обяз.) | Входной аудиофайл (любой формат, который читает ffmpeg) |
| `--engine` | `gigaam` | Движок ASR |
| `--variant` | `e2e_rnnt` | Вариант модели: `e2e_rnnt`, `e2e_ctc`, `rnnt`, `ctc` |
| `--device` | `auto` | `auto` (cuda→mps→cpu), либо явно `cuda`/`mps`/`cpu` |
| `--format` | `txt_timecoded` | `txt_timecoded`, `txt_plain`, `srt`, `json` |
| `--granularity` | `coarse` | `coarse` — крупные окна ~20-24с (для чтения); `fine` — короткие реплики ~5-7с (для субтитров) |
| `--out-dir` | рядом с исходником | Каталог для результата |
| `--dry-run` | — | Показать план без запуска |

## Графический интерфейс

Если не хочется командной строки — есть окно:

```bash
transcribe-ru-gui
```

Кнопкой «Выбрать…» указываете аудио- или видеофайл, выпадающими списками —
формат/вариант/устройство, жмёте «Транскрибировать». Идёт прогресс-бар, по
завершении файл сохраняется рядом с исходником, и **автоматически открывается
папка с результатом** (Finder на macOS, Проводник на Windows).

**Пакет:** в том же окне можно выделить **сразу несколько файлов** (Cmd/Ctrl- или
Shift-клик) — модель загрузится один раз, и файлы обработаются по очереди без
остановки; в строке статуса видно «Файл 3 из 20». Битый файл не прерывает пакет —
в конце покажет, сколько готово и что не удалось. Результат каждого — рядом с его
исходником. Для папки целиком есть CLI-скрипт `scripts/batch_transcribe.py`
(с resume — пропускает уже готовые):

```bash
python scripts/batch_transcribe.py --src /путь/к/папке   # + --format/--granularity/…
```

Чтобы запускать **двойным кликом без терминала**, один раз создайте ярлык:

```bash
transcribe-ru-gui --install-shortcut
```

Появится `~/Desktop/TranscribeRU.command` — двойной клик открывает окно (при
первом запуске macOS попросит подтвердить запуск).

## Форматы вывода

| Формат | Расширение | Что внутри |
|--------|------------|------------|
| `txt_timecoded` | `.txt` | Блоки `ЧЧ:ММ:СС` + текст сегмента (по умолчанию) |
| `txt_plain` | `.txt` | Сплошной текст без тайм-кодов |
| `srt` | `.srt` | Стандартные субтитры с индексами и `-->` |
| `json` | `.json` | `[{start, end, text}, …]` + метаданные (движок, вариант) |

## Гранулярность сегментов (`--granularity`)

Управляет длиной сегментов на выходе — ортогонально формату:

- **`coarse`** *(по умолчанию)* — один сегмент на речевое окно (~20–24 с). Удобно
  читать и «собирать смысл».
- **`fine`** — короткие реплики ~5–7 с через пословные таймстампы модели. Разрыв
  идёт по концу предложения, паузе и длине строки. Для субтитров с точным
  таймингом (особенно с `--format srt`).

В окне (GUI) — выпадающий список «Детализация». Режим `fine` опирается на
пословную разметку `e2e`-вариантов; на «сырых» `rnnt`/`ctc` (без пунктуации)
реплики режутся по паузам и длительности.

## Варианты модели GigaAM-v3

| `--variant` | Особенности |
|-------------|-------------|
| `e2e_rnnt` *(по умолчанию)* | RNN-T + пунктуация и нормализация из коробки |
| `e2e_ctc` | CTC + пунктуация/нормализация; легче и быстрее, чуть менее точно |
| `rnnt` | «Сырой» RNN-T без пост-обработки текста |
| `ctc` | «Сырой» CTC без пост-обработки |

Для большинства задач подходит дефолтный `e2e_rnnt`. RNN-T обычно точнее,
CTC — быстрее и легче.

## Структура проекта

```
src/transcribe_ru/
├── core.py          # Segment, TranscriptResult; оркестрация нарезка→движок→сборка
├── runner.py        # transcribe_to_file — общая связка для CLI и GUI
├── engines/
│   ├── base.py      # ABC Engine + реестр ENGINES (точка расширения)
│   └── gigaam.py    # движок GigaAM-v3
├── segmentation.py  # silero-vad: аудио → окна <25 с
├── audio.py         # ffmpeg → 16 кГц mono float32
├── formatters.py    # сегменты → txt_timecoded / txt_plain / srt / json
├── device.py        # авто-выбор устройства cuda > mps > cpu
├── cli.py           # argparse, прогресс в stderr
└── gui.py           # окно tkinter поверх runner
```

## Добавление нового движка

1. Создайте файл в `engines/`, унаследуйте `Engine` и зарегистрируйте его:

   ```python
   from transcribe_ru.engines.base import Engine, register

   @register("myengine")
   class MyEngine(Engine):
       name = "myengine"

       def load(self, device: str) -> None:
           ...  # ленивая загрузка модели

       def transcribe_segment(self, wav, sr: int) -> str:
           ...  # одно окно <25 с → текст
   ```

2. Запускайте: `transcribe-ru --engine myengine --audio file.opus`.

Ядро само декодирует аудио и режет его на окна — движку приходит готовый
numpy-кусок, ему остаётся вернуть текст.

## Точность на доменных терминах

Если в аудио звучит узкоспециальная лексика (термины предметной области, имена,
жаргон), модель систематически заменяет незнакомые слова на созвучные знакомые —
это называется **substitution errors** на **out-of-vocabulary** лексике, и общий
показатель качества (WER) такие ошибки почти не видит.

Что это за явление, чем его правильно измерять (**EER** вместо WER), какие методы
применимы к RNN-T/CTC-архитектуре GigaAM, и — главное — **грабли пост-коррекции,
проверенные на практике** (омонимия, составные слова, падежи, галлюцинации
LLM-исправления): **[docs/domain-terms-accuracy.md](docs/domain-terms-accuracy.md)**.

Короткий вывод: точность дешевле готовить до распознавания (глоссарий, boosting),
чем чинить после — искажённый термин расползается по всем производным документам.

## Решение проблем

- **`ffmpeg не найден`** — установите ffmpeg (см. «Установка») и проверьте, что он
  в `PATH` (`ffmpeg -version`).
- **Очень медленно** — вероятно работает на CPU. На Apple Silicon используйте
  `--device mps` (или `auto`), на NVIDIA — `--device cuda`.
- **Долгий первый запуск** — это разовое скачивание весов (~430 МБ) в
  `~/.cache/gigaam`; повторные запуски берут модель из кэша.
- **Ошибка установки про Python/колёса** — пересоздайте venv на Python 3.11/3.12.
- **Windows + кириллица в имени пользователя** (`C:\Users\Пользователь\…`) —
  библиотеки на C++ (libtorch, sentencepiece) не открывают пути с не-ASCII
  символами. Быстрый установщик это уже учитывает: ставит проект в ASCII-папку
  `C:\TranscribeRU`, держит кэш модели в `C:\gigaam_cache` (через переменную
  `GIGAAM_CACHE_DIR`) и ставит пакет без editable-режима. При ручной установке
  выбирайте папку без кириллицы и задайте `GIGAAM_CACHE_DIR` на ASCII-путь.
- **`install.bat` сразу падает с ошибками вида `Missing closing '}'` или
  `Unexpected token`** — это старая версия установщика. Windows PowerShell 5.1
  читал `install.ps1` в cp1251, и русский текст ломал разбор. Скачайте свежие
  `install.bat` и `install.ps1` и запустите снова. Установщик теперь также
  совместим с PowerShell 5.1 при скачивании модели: ретраи, TLS 1.2, недокачанный
  файл не принимается за готовый. Если модель раньше скачалась не до конца
  (падение при загрузке), удалите `C:\gigaam_cache`: установщик скачает её заново.
- **Ярлык на Windows не открывается** — посмотрите `%LOCALAPPDATA%\TranscribeRU\
  error.log`: окно пишет туда трейсбек, если запуск упал (ярлык работает через
  `pythonw`, который иначе скрыл бы ошибку).

## Разработка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e '.[dev]'
pytest                 # юнит-тесты (быстрые, без скачивания модели)
pytest -m slow         # интеграционный тест GigaAM (реально качает модель)
```

Логика покрыта юнит-тестами через инъекцию зависимостей (torch/ffmpeg/модель не
требуются). `gui.py` — тонкий слой над `runner` и проверяется ручным запуском.
