# TranscribeRU — GUI (окно на tkinter) — дизайн

Дата: 2026-05-30
Статус: утверждён к реализации

## 1. Назначение

Простое графическое окно для запуска транскрипции на Mac без ввода команд с
путями. Пользователь выбирает аудиофайл системным диалогом, задаёт формат/вариант/
устройство выпадающими списками и жмёт «Транскрибировать». Результат сохраняется
файлом рядом с исходником (как в CLI).

Это пересмотр исходного решения «GUI вне рамок» (раздел 12 базового дизайна):
GUI добавляется как тонкий слой поверх существующего ядра, логика не дублируется.

## 2. Архитектура

Ключевой принцип: **окно не содержит логики транскрипции**, а переиспользует
ядро через новый общий модуль.

- **`src/transcribe_ru/runner.py`** (новый) — оркестрация в одной функции:
  ```python
  def transcribe_to_file(
      audio_path, *, engine="gigaam", variant="e2e_rnnt", device="auto",
      fmt="txt_timecoded", out_dir=None, on_progress=None,
      # точки инъекции для тестов:
      transcribe_fn=None, get_engine_fn=None, select_device_fn=None,
  ) -> Path
  ```
  Внутри: `select_device(device)` → `get_engine(engine)` → `EngineCls(variant=variant)`
  → `core.transcribe(...)` → `formatters.format_result(...)` → запись файла. Возвращает
  путь результата. Также экспортирует `output_path(audio_path, fmt, out_dir) -> Path`
  (перенесена из `cli`).
- **`src/transcribe_ru/cli.py`** (рефакторинг) — `main` парсит аргументы, печатает
  прогресс/итог, но саму работу делегирует `runner.transcribe_to_file`, форвардя
  точки инъекции. `output_path` ре-экспортируется из `runner` (совместимость).
- **`src/transcribe_ru/gui.py`** (новый) — окно tkinter, тонкая проводка: собирает
  параметры из виджетов, запускает `runner` в фоновом потоке, рисует прогресс.
- **`pyproject.toml`** — console-script `transcribe-ru-gui = transcribe_ru.gui:main`.

## 3. UI

Одно окно, поля сверху вниз:
- **Файл**: поле (read-only) + кнопка «Выбрать…» → `filedialog.askopenfilename`
  с фильтром аудио.
- **Формат**: `txt_timecoded` | `txt_plain` | `srt` | `json`.
- **Вариант**: `e2e_rnnt` | `e2e_ctc` | `rnnt` | `ctc`.
- **Устройство**: `auto` | `cuda` | `mps` | `cpu`.
- **Кнопка «Транскрибировать»** (блокируется на время работы).
- **Прогресс-бар** + строка статуса.

`out_dir` в UI нет — сохраняем рядом с исходником.

## 4. Поток выполнения (потокобезопасность tkinter)

tkinter не потокобезопасен — виджеты трогает только главный поток.

1. Клик → проверка выбранного файла → блок кнопки.
2. Фоновый `threading.Thread` зовёт `runner.transcribe_to_file(..., on_progress=cb)`.
3. `cb` (в фоне) только кладёт `(done, total)` в `queue.Queue`; виджеты не трогает.
4. Главный поток через `root.after(100, poll)` читает очередь и обновляет прогресс.
5. Завершение: статус «Готово: путь», разблок кнопки. Исключение
   (нет ffmpeg и т.п.) → `messagebox.showerror` с понятным текстом + разблок.

## 5. Запуск двойным кликом

Помимо команды `transcribe-ru-gui`, генерируем `.command`-ярлык для запуска из
Finder без терминала: команда `transcribe-ru-gui --install-shortcut` создаёт на
Рабочем столе `TranscribeRU.command` (с строкой запуска через текущий интерпретатор)
и делает его исполняемым. Двойной клик открывает окно.

## 6. Тестирование

- **`runner.py`** — полностью по TDD (`test_runner.py`): оркестрация с fake-движком
  и инъекциями, путь вывода, проброс прогресса, выбор устройства.
- **`cli.py`** — существующие тесты сохраняются: `main` по-прежнему принимает
  точки инъекции и форвардит их в `runner`; `output_path` доступна через ре-экспорт.
- **`gui.py`** — БЕЗ автотестов (создание `tk.Tk()` требует дисплея; в headless
  падает). Проверяется ручным запуском. Это согласованное исключение из TDD —
  вся тестируемая логика вынесена в `runner`.

## 7. Вне рамок (YAGNI)

- Пакетирование в `.app`, иконки, подпись.
- Пакетная обработка нескольких файлов (пока один файл за раз).
- Показ текста результата в окне и кнопка «Показать в Finder» (отклонены при
  брейншторминге — только сохранение файла рядом).
- Выбор папки вывода в UI.
